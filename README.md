# 留待明日

打开 `index.html` 即可游玩，也可将本文件夹作为静态网页发布到 GitHub Pages。网页和图片均在本文件夹内，无需安装运行依赖。

开场白使用 `content/开场白.md` 中的五段原文。当前浏览器首次游玩先显示四页操作说明，由玩家手动翻页，可返回上一页。最后一页必须选择「开启音乐」或「关闭音乐」后才开始，两个选项均不预选；音乐设置会保留，之后仍可用右上角开关调整。看过旧版说明但尚未选择音乐的玩家，只补看最后一页。随后开场白全屏居中渐显渐隐，最后经过黑场与「始」字画面进入正文；后续游玩自动跳过；右上角回顾提示在最初对白开始时从右侧滑入，展示四页正文后向右滑出，点击回顾后本次游玩不再提示。回顾期间暂停正文，结束后恢复原位置。切到后台会暂停开场白计时。正常动画模式下，开场白总长 30 秒；结语前十二段总长 60 秒，骤黑、渐亮至纯白的转场 2.16 秒，追加四段及结束过渡合计 25 秒，结语正文总长 87.16 秒；存活结局到结语另有 4 秒过渡（淡出 1.5 秒、黑屏停留 2 秒、淡入 0.5 秒），与正文时长分开计算。「始」「终」字画面各另计 2.4 秒，说明页由玩家自行翻页，不计入上述时长。每部分包含淡入、文字停留、淡出及段间停顿，按字数分配时间；最后三段的停留仍逐步拉长。

生还正文结束后播放 `content/结语.md` 的十二段原文：沿用开场白的居中渐显渐隐，背景逐段过渡到暖白，随后画面骤黑 0.16 秒，用 1.8 秒逐渐亮至纯白，纯白停留 0.2 秒后再进入 `content/结语_尾声.md` 的四段追加文字。文字动画沿用原样，四段分别采用横排、双列竖排、左对齐段落和放大的居中排版。共十六段，全部结束后显示亮色「终」字画面，再自动返回主页。每次成功生还都会播放，死亡结局不播放。

正文以 `content/游戏文案_留待明日.md` 为唯一来源，分支规则依据同目录的 `制作说明与参考.md`。主角固定为维克多·弗兰克尔；对白、配角和分支包含文学改编，五条死亡路线为假设分支。

- 8 章、56 个场景，包含序章、5 条完整死亡支线及生还后的两种任务。
- 条件段落按玩家先前的选择显示；复述会使用实际选过的笑话原话。
- 旁白、环境和心理独白按段落或段落群显示；对白正文只显示 `“台词”`，人物名字单独显示在线上方，每句话单独停顿。默认由玩家手动继续。开启自动阅读后，旁白和对话会连续播放，到下一个选项时停止；快进直接补全文字并快速推进旁白、对话和场景，直到下一个选项。时间地点字幕无外框，居中渐显，停留 1.5 秒后淡出并自动进入正文（淡入 0.6 秒、淡出 0.4 秒另计）。字幕期间灰显自动按钮，原有自动模式会在字幕后继续，快进会缩短字幕展示。暂停及切到后台会保留字幕的剩余时间。
- 选项页不预选答案，空格和背景点击不能跳过选项；再次到达时标注上次选择。死亡结局页显示对应死因；死亡后可回到影响本次结局的关键选择，回退后的选择状态重新计算。
- 阅读设置提供五档自动翻页速度，与逐字速度分开调节。
- 主页「从头开始」开启新一轮游戏，「流程图」可回到已解锁节点。发现新节点后，按钮显示「流程图（解锁了新的节点！）」；查看流程图后清除提醒，刷新会保留尚未查看的状态。
- 解锁新成就后，主页按钮显示「成就（解锁了新成就！）」；进入成就页后恢复「成就」。未查看状态保存在当前浏览器，刷新后仍保留，重复获得已解锁成就不会再次提醒。
- 保留原有插画、美术风格、移动端布局、流程图、12 项成就、回看、阅读设置（字号、行距和速度）、3 个手动存档及逐页自动存档。

空格 / Enter 继续；Esc 暂停；1 / 2 选择；H 隐藏或恢复正文。存档、节点和成就存于当前浏览器，不能跨设备同步。清除网站数据会清除存档。

本稿使用独立的本机记录空间；进入网页后从新稿序章开始。前一个剧本的存档与阅读日志不会载入本稿。

本轮剧情校对、人物首次介绍和前情衔接详见 `content/剧情校对记录.md`。晚霞分支扩写为一次完整的驻足观看，先显示原图，再渐变到 `assets/sunset-open-sky.png`；留在铺上的路线不会显示晚霞图。正文修改后，旧版本存档会从当前场景开头继续，保留选择与成就、清除旧回看文本。

## 字体

## 页面与背景过渡

主页、流程图、成就与正文之间使用短黑场过渡；正文切换场景、段内换图或进入时间地点字幕时，也先淡出至黑屏，停留 0.12 秒后淡入新画面。正文换页、选项、操作说明和阅读面板使用轻量渐入，选项确认与弹窗关闭有渐出。读档与死亡重选在黑场中恢复状态，过渡期间阻止重复输入。原有开场白、结语和「始／终」时长不变；系统开启减少动态效果时，额外过渡会直接完成。

自动模式按页显示全文，显示倒计时并按五档速度翻页。快进每页约 0.13 秒，跨过对话与字幕；两者均在选项处停止。手动模式仍按段落或逐句点击继续。暂停、弹窗与页面切换会清理旧计时，避免迟到的翻页回调。

背景只有实际加载成功后才提交到主图层，再以旧图渐隐露出新图，并预取相邻场景的插画。晚到的旧请求不会覆盖新场景；加载失败或超时会自动重试一次，仍失败则保留当前图并提供「背景未加载，点击重试」。

## 场景配乐

根据 `assets/musics/` 文件名后的中文说明，按较长的剧情段落安排全部 56 个场景。冬季营地、病营与撤营、获释后分别持续共用一首音乐，段内选项和小场景不换曲；晚霞配乐延续到清晨。死亡支线入口沿用前一段配乐，出现身体不适、无法支撑或明确危险时才淡入紧张配乐；提示位置由正文中的隐藏配乐标记控制，读档会恢复当前页应有的配乐。正常生还正文换曲 4—5 次，开场白与生还结语仍使用指定曲目。连续场景的同一首配乐保持播放，不因翻页重头开始；换曲约 1.6 秒交叉淡化。

开始菜单、流程图和成就页保持静音，返回菜单时停止当前音乐。音乐在进入开场白或正文后按开关设置播放，首次交互解锁浏览器音频；游玩提示最后说明右上角音乐开关，并建议佩戴耳机。右上角可开关，「暂停 → 阅读设置」可调音量。打开阅读面板时降低音量，切到后台时暂停。网页使用 `assets/musics/web/` 中的小体积 AAC 副本，原始 FLAC 不变；完整映射、来源校验和构建方法见该目录 README。

死亡配乐切入点：夜班线在第四天穿错木鞋、显出疲惫失常时；监工线在右臂抬不起来时；劳役线在眼前开始发黑时；报复线在被拖回病区时；转运线在木棚上栓、闻到危险气味时。到站后的劳役营字幕处先转入平缓日常配乐，避免夜班线提前沿用到站的紧张配乐。



# 请看我

## 简介

《留待明日》是一款第一人称文字分支游戏，以弗兰克尔的集中营经历为原型。你将阅读故事，通过选择探索生命的意义。游玩约十五分钟。点击或按空格继续阅读，遇到选项时须作出选择。你可以随时暂停并保存进度。失败后，可返回上一个选择重新尝试。设置中可调整文字布局和播放速度。建议佩戴耳机，音乐可在右上角开关。选择不计分，请按自己的节奏游玩。

## 制作说明与AI使用说明

这个作业或者说这部作品是我们与AI共同完成的。接下来允许我把整个流程娓娓道来。

首先，我们阅读了全书，提取出第一部分（集中营中的经历）里的典型事件，以及第二部分（理论部分）中的理论框架。接着，我们尝试二次创作，将刚选出来的典型事件串联成比较错综复杂的流程图，并作为后续故事的骨架。在流程图的每个选项中，我们尝试将其与第二部分的理论，即一些“意义”进行关联。至此，整个故事的雏形已经基本确定。

故事的文案是由AI生成的。但为了让这些文案更有“人”味一点，我们特意让AI大量参考了陀思妥耶夫斯基的作品中的语言风格（这样选择的原因可能是因为陀思妥耶夫斯基作品冷峻的基调比较与集中营契合），并给了AI一些黑名单语言，比如说滥用“不是……而是……”、短句对话、滥用重复、滥用升华等等……这样，整个文案经我们过目，基本已经不怎么有那种令人生厌的套路味道。

随后，根据这个调整好的文案，我们让AI开始写程序，把这些文案、选项做成一个可互动的整体。然后用冗长的语言、来回的对话打磨美术风格，选了一些音乐（个人喜好，歌曲来自中国台湾作曲家10lulu）。在一轮一轮对话的等待和调整之后，勉强产出了一个差强人意的拙作。

我们认为在这个过程中，AI的使用和辅助是很有“意义”的，它能帮助我们很快地丰富我们搭好的枝干，并扩充其语言的叶，画出我们脑海中设想的画面……如此，我们的注意力得以专注于更深层的，故事的内涵的设计。

## 附录：与AI的对话

我用AI整理了一下在整个制作过程中我们与AI的讨论过程，大致如下：

### 1. 根据已有材料完成后续游戏内容

我首先要求 AI 参考文件夹中的提示词、剧本和已经完成的开始界面，继续制作游戏后续部分。对于新增插画，我特别强调应参考已经画好的图片，保持美术风格一致，避免不同场景之间出现明显的视觉差异。

这项要求确定了项目的基本工作方式：以我提供的材料为基础开展制作，并延续已有设计。

### 2. 确认手机端浏览与网页存档能力

在游戏初步形成后，我询问当前网页能否满足手机端浏览，以及部署到 GitHub Pages 后是否仍能实现存档、读档。

这些问题主要关注游戏能否方便地分享给他人，以及玩家关闭页面后能否继续游玩，而不仅是网页能否在本地运行。

### 3. 了解 GitHub 上传和网页发布方法

我询问在已经执行 `git init` 和 `git add .` 的情况下，应该使用哪些指令上传远程仓库；随后又询问如何将仓库发布为网页，以及网页地址如何确定。

在这一阶段，我明确表示只需要一般性的方法说明，不需要 AI 代为操作。之后也说明 GitHub 上传已由我完成，不必再次检查或上传。

### 4. 明确文字显示与手动翻页规则

我要求区分不同类型的文字：旁白、环境描写和心理独白按段落或段落群显示，显示完成后等待玩家点击；人物对话则逐句显示，每句话结束后都应暂停。

最初，对话采用“人物：台词”的形式。这项要求的重点是让阅读节奏与文本类型相匹配，避免大段文字连续推进，导致玩家来不及阅读。

### 5. 使用重写稿全面替换旧文案

在我重新撰写全部文案后，我要求 AI 将旧文案全部替换，不保留旧版本内容。由于新稿仍沿用原来的大纲，场景与美术风格基本保持不变。

当文件夹内出现两份改写稿时，我明确指定以“原创重写”文件夹中的《游戏文案_留待明日.md》及配套制作说明为准，统一后续制作所依据的文本版本。

### 6. 防止选项被误跳过或默认选中

我指出，选项界面不能通过空格或点击背景直接跳过，必须等待玩家主动选择。同时，选项不应预先默认选中某一项，以免玩家误操作。

对于已经游玩过的内容，我允许标注玩家上次选择的选项，但要求将“历史选择提示”与“当前默认选择”区分开。

### 7. 解决死亡重试可能形成的循环

我发现，部分死亡结果由较早的铺垫选项触发。如果死亡后只返回最近一次选择，玩家即使改选，也可能仍然无法摆脱死亡结局。

因此，我要求 AI 提出合理的回退方案，并进一步询问其避免死循环的详细规则。这项要求涉及对剧情因果的检查：重试位置应当能够让玩家改变导致失败的关键条件。

### 8. 明确自动播放的适用范围和速度设置

我指出，开头页面及部分其他位置的“自动”按钮虽然可以点击，却没有实际效果。这些位置应将按钮置灰并禁止点击，避免给玩家错误反馈。

同时，我明确了自动播放的功能：连续推进文字，直到下一个选项出现时停止；玩家可以在设置中调整播放速度。

### 9. 加入开场白及首次展示规则

我提供了完整开场白，要求放在开始游戏之后，以全屏形式呈现。文字按照我划分的段落居中显示，并采用渐显、渐隐效果，播放结束后逐渐黑屏，再进入正文。

我还要求开场白仅在首次游玩时自动展示。后续游玩应跳过，并提供“开场白已跳过，点击此处回顾”的入口，使玩家既能快速开始，也能重新阅读。

### 10. 为存活结局加入完整结语

我提供了十二段结语，要求玩家成功达成存活结局后再展示。结语的呈现方式与开场白相近，但背景应逐渐变成亮色。

随后，我又补充了收尾文字，希望从故事中的经历引向玩家自身的生活，并要求在进入这一部分时加入较有冲击力的过渡效果。

### 11. 多次调整开场白和结语时长

在体验后，我认为开场白和结语持续时间过长，先要求整体缩短到原来的零点六倍，并允许结语最后几句逐渐拉长。

在进一步询问具体时序后，我将目标明确为：开场白三十秒，结语前十二段六十秒，收尾部分二十五秒。这项修改旨在保留情绪表达，同时减少等待感。

### 12. 增加分多页展示的游玩教学

我要求在开场白之前说明暂停、保存进度、继续游戏、按章节进入、自动播放、快进、文字布局和速度设置等功能，并介绍失败后的重试方式。

我允许 AI 将说明改写得更自然、全面，但要求阅读时间不要过长。看到一页式说明后，我又提出应分为多页，适当强调重要操作，避免玩家忽略。

### 13. 增加“始”“终”画面并确认字体可用

我要求教学和开场白结束后显示“始”，再进入正文；结语播放完毕后显示“终”，再返回主页。

字体方面，我要求“始”“终”采用类似 EVA 的字体风格，正文使用宋体，并确认实际字体文件可以使用，而不是仅在设计上指定字体名称。

### 14. 完善页面动画并排查播放故障

我要求页面之间尽可能补充黑屏过渡、渐隐和渐显，使界面切换更加完整。

在实际测试中，我又陆续指出自动模式似乎没有翻页、快进存在问题、背景没有自动切换等现象，要求 AI 检查。这些反馈来自实际操作，重点是确认按钮和效果是否真正发挥作用。

### 15. 根据素材说明配置背景音乐

我将音乐放入 `assets` 文件夹，并在文件名后添加中文用途说明，要求 AI 根据这些描述将曲目安排到适合的场景中，切换时采用淡入淡出。

配置后，我进一步询问每个场景对应的音乐，并指出切换过于频繁，要求减少换曲，避免音乐不断重启或打断情绪。

### 16. 排查网页更新后没有变化的问题

当我在 GitHub Pages 页面刷新后仍看不到界面或功能更新时，我询问当前文件如何处理，以及为什么刷新没有变化。

我随后明确，问题发生在已发布的 GitHub Pages 网页，而非本地页面。这一说明帮助区分本地修改、远程上传、网页发布及浏览器缓存等不同环节。

### 17. 通读全流程，检查剧情逻辑和人物介绍

我指出奥托相关情节难以理解，要求 AI 通览完整流程，检查是否还有不合逻辑、交代不清或前后衔接不足的文本。

同时，我要求为具名人物增加出场介绍，交代他们是谁、与主角有什么关系，避免玩家在尚未理解人物身份时就被要求作出选择。

### 18. 扩写晚霞场景并增加插画

由于我特别喜欢晚霞场景，我要求延长选择“出去看晚霞”之后的描写，并增加一张更美丽的晚霞图片。

这项修改不仅涉及文字数量，也涉及场景停留时间和情绪节奏。我希望玩家在这一段获得较充分的观看与感受空间。

### 19. 修复开场白回顾按钮

我在使用中发现“回顾开场白”按钮无法点击，因此单独提出修复要求。

之后，我又调整了该提示的出现方式：只在最初几个对话开始时从右侧进入，经过几页后从右侧退场，避免长期占据游戏画面。

### 20. 统一游戏界面的视觉风格

我对章节提示、作品标题、时间地点提示、暂停界面和选项提出了一组具体修改要求。

其中包括：左上角以较大的“章节编号＋章节名”显示主标题，下方用较小文字显示场景名；取消原有时间地点框，改为画面中央短暂浮现；游玩过程中的文字以白色和灰色为主，灰色表示按钮不可用；暂停界面直接使用“暂停”，并取消金色装饰。

### 21. 多轮调整对话区域与人物名称

我先要求对话框取消金边，改为白色圆角边框，之后又进一步决定完全去掉边框。

最终要求是在原对话框上边缘画一条淡灰色横线，横线以下作为文字区域，并添加轻微半透明背景。人物名称放在横线上方，与正文首字符对齐，字号略大于正文，以便玩家快速识别说话者。

### 22. 统一菜单名称和新增内容提醒

我要求将“按章节开始”改为“流程图”，将“从押送车开始”改为“从头开始”，并同步修改教学中的按钮名称。

此外，每次游玩结束后，如果解锁了新成就或新节点，开始菜单的对应按钮应显示提醒；玩家点击查看后，提醒消失。这样可以让新增内容更容易被发现，又不长期干扰界面。

### 23. 替换结语特效并丰富排版

在查看结语效果后，我认为原特效不够自然，要求改为：画面突然变黑，再逐渐亮起，完全变白后进入后续文字。

后续文字的动画保持不变，但排版可以更有变化，例如采用竖排。修改重点是让转场服务于结语情绪，而不是让特效本身显得突兀。

### 24. 明确音乐提示和开关选择

我要求开始菜单不播放音乐，并在教学末尾提醒玩家本作包含音乐、右上角可以切换开关，以及建议佩戴耳机游玩。

随后，我进一步要求玩家在教学阶段明确选择开启或关闭音乐，而不是直接接受默认状态。进入游戏后，仍保留右上角的切换按钮。

### 25. 统一说话者显示并加强场景过渡

我要求主角说话时，人物名称统一显示为“我”；主角的心理独白则不显示人物名称，避免“我”和具体姓名交替出现造成混淆。

在已有姓名栏的基础上，我又要求正文对话去掉重复的说话者前缀，只保留台词。同时，场景切换加入黑屏，尤其在存活结局进入结语时采用更长的过渡。

### 26. 补充死因并延后死亡音乐

我要求每次死亡后说明死因，让玩家能够理解本次失败发生了什么，而不是只看到统一的死亡提示。

对于死亡线路的背景音乐，我指出其进入过早，要求等到人物开始不舒服、体力不支或出现其他明确危险预兆时再切换，避免提前暴露结果。

### 27. 要求多轮程序与流程检查

在功能逐渐完善后，我要求 AI 检查是否还有程序错误，并在第一次检查后再次提出“再测试一遍，确认无误”。

这部分要求关注完整流程中的可靠性，尤其是自动播放、快进、存读档、死亡重试、背景切换和结局播放等功能之间是否会互相影响。

### 28. 再次检查文案、阅读节奏和音乐安排

除程序问题外，我还要求重新检查文案中是否存在不清晰、逻辑混乱的内容，并判断整体阅读节奏是否合适。

同时，我要求结合剧情判断音乐何时进入、何时切换是否合理。这一轮检查将文字、交互和声音放在同一条游玩流程中考虑，而不是分别处理。

### 29. 调整游玩预估，降低玩家的心理负担

在游玩时长提示被改为较长的预估后，我要求改成“十五分钟”，理由是不要给玩家太大压力。

这项要求体现了我对介绍语气的考虑：说明应帮助玩家开始体验，而不应让玩家在进入游戏前就产生明显的时间负担。

### 30. 撰写简明的游戏介绍

我要求参考 ASD-STE100 的简明表达原则，撰写一段约一百五十字的中文介绍，包含游戏形式、基本操作和游玩注意事项。

介绍需采用单段形式，语言清楚、指令明确，方便作为面向玩家的说明文字使用。
